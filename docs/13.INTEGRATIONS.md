# 13. INTEGRATIONS — External Services

Each integration has an adapter with a development fallback. The app must run with none of these configured.

## Email (Nodemailer SMTP)
- **Adapter:** `backend/src/services/email/`. Interface: `send({ to, subject, html, text, idempotencyKey })` returns `{ status, providerMessageId }`.
- **Real mode:** when `SMTP_HOST` is set, uses Nodemailer. Status becomes `sent` only when the SMTP server accepts the message.
- **Dev mode:** when `SMTP_HOST` is empty, writes the rendered email to the server log (with the recipient masked and secret links replaced by `[REDACTED_LINK]`) and to `Notification` status `logged_dev`. The UI labels these as "Development preview — not delivered".
- **Failures:** recorded in `NotificationDelivery` with `failed` and the provider error (sanitized). Transient errors retried with backoff (max 5 attempts).
- **Providers tested:** none yet. Candidates: any SMTP relay or transactional provider with SMTP access. Verify with a real test inbox before claiming delivery.

## Queue
- **Default:** MongoDB `Job` collection, processed by `npm run worker`. Durable across restarts.
- **Optional:** BullMQ on `REDIS_URL`. Same job types and idempotency keys. Enable only with a managed Redis instance.
- **Switching:** job types are defined once; the adapter chooses the backend at startup and logs which one is active.

## MongoDB Atlas
- Connection string in `MONGODB_URI`. Use a dedicated database user with least privilege.
- Enable IP access list and TLS (default in Atlas).
- Replica set is provided by Atlas, so transactions are available.

## Hosting
| Part | Host | Config |
|---|---|---|
| Frontend | Vercel | Root dir `frontend`, build `npm run build`, env `VITE_API_URL` |
| API | Render web service | Build `npm install --prefix backend`, start `npm run start --prefix backend`, env vars from `.env.example` |
| Worker | Render background worker | Start `npm run worker --prefix backend` |
| Redis (optional) | Managed Redis | `REDIS_URL` |

## Calendar sync, payments, SMS
Not implemented. Consent fields for SMS exist in the model, but no SMS provider is integrated. Payment collection is deferred until a provider is configured.

## Health checks
`GET /health/ready` reports `mongo: ok|down`, `queue: mongo|bullmq`, `email: smtp|dev`. It never reports credentials.
