# 10. FEATURE DEVELOPMENT — How to Add a Feature

## Checklist
1. **Spec:** add or update the item in `PRD.md` (goal, non-goal, acceptance criteria).
2. **Data:** change `DATABASE.md` first if a model or index changes. Add an index only with a query that needs it.
3. **Contract:** add the endpoint to `API.md` (method, path, role, request, response, errors).
4. **Backend:**
   - `validators/<feature>.validator.js` — Zod schemas.
   - `services/<feature>.service.js` — business rules, no Express objects.
   - `controllers/<feature>.controller.js` — thin adapter.
   - `routes/<feature>.routes.js` — attach `requireAuth`, `requireMembership(role)`, rate limiter.
   - `tests/<feature>.test.js` — include authorization and invalid-input cases.
5. **Frontend:**
   - API calls in `services/<feature>Api.js` using the shared Axios client.
   - Form schema in `schemas/<feature>.schema.js` (shared rules mirrored on server).
   - Page in `pages/`, feature components in `features/<feature>/`.
   - Loading, error, empty, and success states.
6. **Audit:** if the feature changes booking, role, settings, waitlist, or offers, write an AuditLog entry and add a test.
7. **Verify:** lint, unit tests, integration tests, build. Manual check on mobile width.
8. **Docs:** update `PROJECT_IMPLEMENTATION.md` status and `TESTING_QA.md` results.

## Definition of ready
- Acceptance criteria written.
- Tenant scope stated (which org, which roles).
- Failure behavior stated (what the user sees when the service is down).

## Definition of done
- All acceptance criteria have a passing test or a recorded manual check.
- No decorative controls.
- Logs redact secrets.
- Migrations or seed updates included when schema changes.

## Example: adding a "no-show fee flag" (hypothetical)
1. PRD: owners can flag a no-show; no money is charged (no payments in MVP).
2. DATABASE: add `Appointment.noShowFlagged: Boolean`, default false.
3. API: `POST /orgs/:orgId/appointments/:id/flag-no-show` — owner, admin.
4. Service: allowed only from `confirmed` status → sets `no_show` and writes history.
5. Test: staff gets 403; other-org ID gets 404; wrong status gets 409.
6. Audit entry created.
