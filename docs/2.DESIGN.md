# 2. DESIGN — SlotSaver UI and Visual System

## Visual direction (from the SlotSaver reference collage)
- Dark navy sidebar and marketing hero.
- Indigo/purple primary actions.
- White cards and light-gray surfaces, rounded corners, subtle shadows.
- Status colors: **green** = confirmed/recovered, **amber** = pending/requested, **red** = cancelled/no-show, **slate** = completed/neutral.
- Professional tables, Recharts charts, day/week/month calendar.

The reference image is used as a visual guide only. It is recreated as real React components, never inserted as a picture.

## Design tokens (Tailwind theme)
| Token | Value (intent) |
|---|---|
| `navy-900` | `#0B1437` — sidebar, hero |
| `indigo-600` | `#4F46E5` — primary buttons |
| `purple-500` | `#8B5CF6` — accents, gradients |
| `success-600` | `#16A34A` — confirmed/recovered |
| `warning-500` | `#F59E0B` — pending |
| `danger-600` | `#DC2626` — cancelled/no-show |
| `surface` | `#F8FAFC` — page background |
| `card` | `#FFFFFF` — cards |

Typography: system UI stack (Inter if loaded), 14px base in app, 16px base marketing. Spacing on a 4px grid. Radius `xl` for cards, `lg` for inputs.

## Components (reusable, in `frontend/src/components/ui`)
Button, Input, Select, Textarea, PasswordInput, Card, Badge (status), Table (sortable, paginated), Dialog (confirmation), Toast, Skeleton, EmptyState, ErrorState, Tabs, Pagination, SearchInput, FilterBar, Calendar (accessible grid + list alternative), StatCard, ChartCard.

## States every data view must handle
- **Loading:** skeletons, not spinners only.
- **Empty:** explanation and a primary action.
- **Error:** message, retry button, request ID shown for support.
- **Success:** toast.
- **Disabled:** reason shown (e.g., "Email is not configured in this environment").

## Layout
- App shell: left sidebar (collapses to a drawer below 1024px), top bar with search, notifications, profile menu.
- Marketing: sticky top nav; hero with dashboard preview; sections for features, how it works, pricing, FAQ, footer.
- Customer booking: single column, step indicator (service → staff → time → details → confirm), max width 640px.

## Accessibility
- WCAG 2.2 AA contrast for text and status badges (badge text is never color-only; always includes a label).
- Visible focus rings (`ring-2 ring-indigo-500 ring-offset-2`).
- All form fields have associated labels and error text linked with `aria-describedby`.
- Calendar: keyboard arrow navigation; a list view is always available.
- Dialogs trap focus and restore it on close.

## Responsive breakpoints
Mobile first: <640px, 640–1023px tablet, ≥1024px desktop. Tables become stacked cards below 768px.
