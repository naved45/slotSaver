# 6. AGENTS — Rules for AI Coding Agents Working on SlotSaver

Read this file, `PRD.md`, `ARCHITECTURE.md`, and `DATABASE.md` before changing code.

## Role
Act as a senior full-stack engineer. Make reasonable product and technical decisions, record assumptions in `docs/` when they change the design, and continue without waiting for questions unless a secret or external account is required.

## Hard rules
1. **Verify before claiming.** Do not state that a feature, test, email, or deployment works unless it was executed. Report exactly which commands ran and their results.
2. **Never commit secrets.** Use `.env.example` with placeholders only. Never log passwords, session tokens, reset tokens, invitation tokens, or booking-action tokens.
3. **Tenant isolation.** Every query on a tenant-owned model must include `organizationId`. Never trust an organization ID from the client without a membership check.
4. **Prices and availability come from the server.** Never accept a price or a "slot is free" claim from the browser as truth.
5. **No frontend-only auth.** Protected routes are enforced by the API.
6. **Money** is stored as integer minor units (`priceMinor`).
7. **Time** is stored as UTC. Convert to the organization timezone with luxon at the edges.
8. **Do not use in-memory timers as the only scheduler.** Use the job store (or BullMQ when Redis is configured).
9. **Do not fabricate** testimonials, logos, metrics, or compliance claims.
10. **Email:** never report "sent" unless the provider returned success. Dev mode status is `logged_dev`.

## Workflow for a change
1. Read the relevant doc (`API.md`, `DATABASE.md`, or `DESIGN.md`).
2. Write or update the test first where practical (booking, permissions, waitlist logic).
3. Implement in the correct layer: route → controller → service → model.
4. Run `npm run lint`, `npm test`, and `npm run build` in the changed app.
5. Update the doc if the contract changed (API, schema, env var).
6. Report results honestly, including failures.

## Code conventions
- JavaScript (ES modules). No TypeScript in MVP.
- Controllers stay thin; business logic goes in `services/`.
- Validate every request body, query, and param with Zod in `validators/`.
- Errors are thrown as `AppError(status, code, message)` and handled centrally.
- Use `requestId` in logs. Use a logger that redacts configured keys.
- Frontend: components in `components/ui` must be reusable; pages compose features.
- No decorative buttons: every control performs an action or is disabled with a reason.

## Done means
Lint passes, tests pass, build passes, docs updated, and the change was exercised manually or by a test. See `TESTING_QA.md`.
