# 14. TESTING_QA — Test Strategy and Results

## Layers
| Layer | Tool | Location | Scope |
|---|---|---|---|
| Unit (pure logic) | Vitest | `backend/src/tests/unit` | Availability math, slot generation, ranking, token hashing, status transitions |
| API integration | Vitest + Supertest | `backend/src/tests/api` | Auth, tenancy, booking, cancellation, waitlist, jobs — needs MongoDB |
| Frontend unit | Vitest + React Testing Library | `frontend/src/tests` | Forms, validation, states, booking steps |
| Lint | ESLint | both apps | Style and common bugs |
| Build | Vite / Node | both apps | Production build succeeds |
| Accessibility | eslint-plugin-jsx-a11y + manual keyboard pass | frontend | Labels, focus, roles |
| CI | GitHub Actions | `.github/workflows/ci.yml` | Runs lint, tests, build on push and PR |

Integration tests use `MONGODB_TEST_URI` and drop the test database before each suite. They never run against `MONGODB_URI`.

## Required test cases

### Authentication and permissions
- Signup and login success; wrong password; unknown email returns the same message.
- Password reset expiry; reset token single-use; reset revokes sessions.
- Logout revokes the session cookie.
- Staff cannot perform owner-only actions (403).
- Organization A cannot access Organization B data (404).
- Changing an ID in the URL does not bypass authorization.

### Booking correctness
- Availability respects business hours, durations, buffers, staff schedules, existing appointments, closures, and timezone.
- Two concurrent booking requests for the same staff and time: exactly one succeeds (201), the other gets 409.
- Expired holds are released and the slot becomes bookable.
- Rescheduling releases the old slot and reserves the new one; a failed reschedule leaves the old booking intact.
- Cancellation is authorized and recorded in status history.
- Invalid or expired guest tokens are rejected.

### Waitlist recovery
- Cancelled slot selects matching waitlist entries.
- Ineligible entries (wrong service, wrong staff, outside time preferences, consent withdrawn) are skipped.
- Declined or expired offer advances to the next candidate.
- Two simultaneous acceptances: one succeeds, one gets 409.
- Retried job does not create a duplicate offer or appointment (idempotency key).
- Recovery analytics count only appointments created by accepting an offer.

### Notifications
- Reminder jobs are scheduled at the configured offsets.
- Rescheduling or cancelling updates pending reminders.
- Duplicate job execution sends at most once (idempotency key).
- Failed delivery is recorded as `failed` with sanitized error.
- Dev mode without SMTP writes `logged_dev`, never `sent`.

### Frontend
- Login and signup validation messages; password show/hide.
- Public booking: pick service → staff → slot → details → confirmation.
- Cancel and reschedule from a guest link.
- Accept a waitlist offer; decline an offer.
- Dashboard loading, error, and empty states.
- Responsive navigation opens and closes at mobile width.

## Manual checks (before each release)
- Sign up → verify (dev log) → onboarding → create service → add staff → publish booking link.
- Book from a phone-width viewport; cancel from the guest link; confirm the slot reopens.
- Cancel an appointment with a waitlisted customer; accept the offer from the email link.
- Keyboard-only: complete the booking flow without a mouse.

## Known gaps in verification
- The browser test covers the main happy paths and one error path. It does not cover the waitlist offer and accept flow in the browser, mobile viewport checks, or keyboard-only operation.
- Screen reader testing has not been done.
- The CI workflow has not been executed on GitHub.
