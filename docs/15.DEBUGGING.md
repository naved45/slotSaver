# 15. DEBUGGING — Troubleshooting

## First steps
1. Read the error's `requestId` and search the backend logs for it.
2. Check `GET /health/ready`.
3. Confirm `.env` values are set (names only; never paste secret values into issues).
4. Re-run the failing test alone: `npx vitest run <file> -t "<name>"`.

## Common problems

| Symptom | Likely cause | Fix |
|---|---|---|
| `MongoServerSelectionError` | Mongo not running or wrong `MONGODB_URI` | Start Docker container; check port 27017 |
| `Transaction numbers are only allowed on a replica set member` | Local Mongo is standalone and the code requested a transaction | The code falls back automatically; if it does not, start Mongo with `--replSet rs0` |
| 401 on every request in the browser | Cookie not sent: frontend and API on different sites, or `SESSION_COOKIE_SECURE=true` on http | Use `localhost` for both in dev; set `SESSION_COOKIE_SECURE=false` locally |
| 403 "Invalid origin" on POST | `APP_ORIGIN` does not match the browser origin | Set `APP_ORIGIN=http://localhost:5173` |
| 403 "Missing X-Requested-With" | Custom client not sending the header | Use the shared Axios client in `frontend/src/services/apiClient.js` |
| Booking returns 409 unexpectedly | Slot already booked, or a hold has not expired | Check `Appointment` and `SlotHold`; holds expire automatically |
| Reminder shows `logged_dev` | No SMTP configured | Expected in development; add SMTP vars to send |
| Jobs never run | Worker not started | Run `npm run worker --prefix backend` |
| Job stuck in `running` | Worker crashed mid-job | Lease expires after `lockedUntil`; the job is re-claimed automatically |
| Calendar shows wrong times | Organization timezone wrong, or a display used the browser timezone | Check `Organization.timezone`; display uses the org zone |
| `E11000 duplicate key` on Appointment | Two bookings for the same staff and start time | This is the double-booking guard working; surface a 409 to the user |
| CORS error | `APP_ORIGIN` missing the frontend origin | Add the origin; comma-separate multiple |
| Vercel build fails on env | `VITE_API_URL` not set in Vercel project | Add the variable and redeploy |

## Reporting a bug
Include: steps, expected vs actual, requestId, environment (local or hosted), and the relevant test output. Never include passwords, tokens, or cookie values.
